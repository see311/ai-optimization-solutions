# 深入源码：Hermes Agent 如何实现 "Self-Improving" - 总结

## 文章核心观点

本文深入解析了 Hermes Agent 的 Self-Improving（自我进化）机制，对比分析了其与 OpenClaw 的核心差异。

## 三大子系统

### 1. Memory（记忆系统）
- **设计理念**：两个纯文本文件（MEMORY.md + USER.md），严格字符限制（2200 + 1375 chars）
- **冻结快照**：会话开始时冻结，保证前缀缓存省计费
- **声明式事实**：Memory 要求声明式而非命令式，避免限制 Agent 灵活性
- **容量管理**：超限返回所有条目给模型，让模型主动决策淘汰

### 2. Skill（技能系统）
- **核心价值**：把"做过的事"变成"会做的事"，Agent 踩坑后自动提炼成可复用 Skill
- **创建触发**：工具调用 5+ 次、踩坑修复、用户纠正等场景
- **自我修补**：使用 fuzzy_find_and_replace 做局部 patch，保留稳定部分
- **渐进式加载**：轻量索引 + 按需加载完整内容，避免 Token 浪费

### 3. Nudge Engine（触发引擎）
- **双计数器**：Memory 按回合计，Skill 按迭代计
- **后台 fork**：静默审查，不打扰用户，输出重定向 /dev/null
- **防递归**：Review Agent 禁用自身 nudge

## 关键对比：Hermes vs OpenClaw

| 维度 | OpenClaw | Hermes |
|------|----------|--------|
| Skill 来源 | 手写/社区装 | Agent 自主创建 |
| 学习方式 | 靠人喂 | 自己长 |
| Memory 模式 | 纯追加膨胀 | 容量限制+主动淘汰 |
| 进化能力 | 一次学会一直会用 | 越用越强 |

## 安全机制
- Memory 内容扫描：防止 prompt injection
- Skill 安全扫描 + 自动回滚
- RDSHermes 增加：密钥加密托管、审计链路

## 核心结论
- **设计哲学分野**：一个靠人喂，一个自己长
- **护城河论**：模型智能被商品化后，真正的护城河是 Agent 在工作中积累的领域知识
- **效率提升**：K8s 部署从 12 次调用/2 错误 → 6 次调用/0 错误
