# RAG 检索失效：四大根源与全链路排查实战

## 问题现象

用户文档显示"入库成功"，但实际问答时模型频繁回复"未找到相关信息"。

## 四大失效根源

| 失效模式 | 症状 | 根因 |
|---------|------|------|
| **Chunk 粒度失配** | 关键信息被切割 | 固定长度分割，忽略语义边界 |
| **Embedding 不匹配** | 相似度计算失真 | 通用模型 vs 垂直领域 |
| **HNSW 参数过低** | 高维召回遗漏 | ef_search 配置不足 |
| **元数据过滤误杀** | 合法文档被排除 | 字段缺失/格式不一致 |

## 五步排查法

```
用户问题 → 知识库覆盖？ → 文档入检索链？ → 向量生成？ → 上下文拼接？
```

## 解决方案：一致性保障体系

### 1. 文档生命周期状态机
```
入库存疑 → 向量化中 → 索引完成 → 检索就绪
```

### 2. Embedding 质量双校
- 入库时：验证向量维度/分布
- 检索时：验证 query 向量质量

### 3. 自适应 Chunk 策略
- 按标题/段落语义切分
- 动态重叠窗口

### 4. 检索链路可观测矩阵

| 阶段 | 指标 | 告警阈值 |
|-----|------|---------|
| 向量化 | 成功率 | <99% |
| 索引 | 延迟 | >500ms |
| 检索 | 召回率 | <80% |
| 拼接 | 长度 | >4096 |

### 5. 元数据兜底逻辑
```python
# 过滤前先检查字段存在性
if metadata.get('type') and validate_format(metadata['type']):
    apply_filter(...)
```

## 总结

RAG 检索失效的核心是 **四层状态不一致**：入库 → 向量化 → 检索 → 拼接，任何一环断裂都会导致最终失效。

**最佳实践**：
1. 混合检索（向量 + BM25）+ Reranker
2. 全链路日志追踪
3. A/B 测试验证优化效果
