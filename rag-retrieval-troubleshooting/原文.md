# RAG 检索失效全链路排查指南

> 原文来源：头条文章 - https://m.toutiao.com/is/paQGtemK5yw/

## 主要问题现象

用户上传的知识库文档显示"入库成功"，但在实际问答中模型仍然频繁回复"未找到相关信息"。

## 排查顺序

1. 确认用户问题是否可被知识库覆盖
2. 验证文档是否真正进入检索流程
3. 检查 embedding 向量是否生成并存储
4. 分析检索请求的 embedding 质量
5. 审查上下文拼接逻辑

## 四类典型失效模式

### 1. 切片段粒度失配导致语义断裂

长文档被粗暴分割为固定长度 chunk，导致关键信息被拆散。

### 2. Embedding 模型与业务领域不匹配

使用通用中文 embedding 模型处理专业领域文档，导致相似度计算失真。

### 3. 向量索引配置不当引发召回遗漏

使用 HNSW 索引时，ef_search 参数设置过低，导致高维空间中近邻搜索不充分。

### 4. 元数据过滤逻辑误杀有效结果

检索时附加了文档类型、时间范围等过滤条件，但因元数据字段缺失或格式不一致，导致合法文档被排除。

## 核心原因

**入库、向量化、检索、拼接四层状态不一致**，缺乏端到端一致性保障。系统缺乏"文档-向量-检索"三元组的状态机管理。

## 解决方案：构建可观测的检索一致性保障体系

1. 引入文档生命周期状态机
2. 实施 embedding 质量双校验证
3. 动态调整切块策略
4. 建立检索链路可观测性矩阵
5. 元数据兜底过滤逻辑

## 技术补丁包

- 文档生命周期状态机实现
- Embedding 质量双校验证机制
- 动态切块策略引擎
- 检索链路可观测性矩阵
- 元数据兜底过滤逻辑

---

## 风险与边界

在实际 RAG 系统中，混合检索（向量 + BM25）与重排序（Reranker）是业界共识的解决方案。关键在于从入库到检索全链路的可观测性建设。
