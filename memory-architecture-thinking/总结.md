# Memory架构与思考 - 核心要点总结

## 一、Memory的本质

**核心定义**：Memory是Agent在长期交互中积累、可被检索与利用的记录/知识/经验库。

**三大核心命题**：

1. **Memory不是"存储"，而是外部状态**
   - 价值不在于"存了多少历史"，而在于历史到当前决策的通道是否有效
   - Memory = 把历史转成当前可用信息的通道

2. **最小闭环是(Ledger, Views, Policy)三件套**
   - **Raw Ledger**：append-only权威记录，保证可审计、可回滚
   - **Derived Views**：派生视图（向量/关键词/KG/TKG/timeline），可回溯到Ledger
   - **Policy**：控制读写策略，决定何时读/写、如何更新，通过RL训练

3. **Memory基本单位是event序列**
   - event是Ledger的数据形态；views/policy是能力形态
   - event序列太底层，必须通过views和policy转化为可用能力

## 二、System 1 + System 2架构

- **System 1**：LLM Agent，负责快速推理、规划、工具调用
- **System 2**：Agentic Memory（慢速循环），负责PreThink→Retrieve→Evidence积累→Early Stop
- 两者"相对正交"，可独立优化，通过Context Bridge连接

**核心价值**：牺牲一点Memory上限，换取通用Agent性能不受影响、记忆可插拔/可迁移/更易归因。

## 三、非参数化逼近参数化Memory

- **参数化**：经验写入模型权重（训练阶段完成）
- **非参数化**：经验写在外部状态，通过检索/聚合/注入影响输出

**关键机制**：外部记忆对模型输出施加可控修正项Δ，改变决策分布而不改权重。

**代表工作**：
- **JitRL**：维护动态经验库，推理时检索相似轨迹对logits加性调制
- **UMEM**：通过语义邻域结构存储"一类问题"的通用解法

## 四、上限瓶颈分析

**三类瓶颈共同决定上限**：

1. **接口带宽**：Memory→System 1的注入量受token/延迟/注意力限制
2. **检索/聚合误差**：views的近似误差会直接污染修正项Δ
3. **Policy可学习性与可控性**：写多污染、写少学不到；UPDATE/DELETE做错会滚雪球

**真正瓶颈往往是policy，而不是存储后端**。

## 五、Policy设计

**核心理念**：把记忆操作彻底工具化，整合进Agent的动作空间。

**RL训练策略（AgeMem）**：
- LTM构建阶段：训练ADD/UPDATE能力
- STM控制阶段：训练FILTER和SUMMARY能力
- 综合推理阶段：解决长程任务

**PreThink-Retrieve-Write协议（InfMem）**：
- PreThink：评估内部知识是否足够，减少不必要检索
- Adaptive Early Stopping：证据置信度达标即停止检索，推理速度提升3.9倍
- SFT→RL训练范式

## 六、记忆单元：结构、时序与压缩

**SimpleMem机制**：
- 存储压缩后的记忆单元，而非原始文本
- 通过Affinity Score进行递推固化，将高亲和力单元合并为抽象表征
- 提升存储效率，Token消耗显著降低

**时序知识图谱（Zep/Graphiti）**：
- 给边加入Temporal Validity，区分"曾经为真"和"当前为真"
- 结合查询时间动态合成"当前真值图谱"
- 相比传统RAG准确率提升18.5%

## 七、时序记忆（核心维度）

**为什么时序是架构骨骼层而非metadata**：
- LLM对时间天然不敏感
- 纯语义检索会把旧事实错当当前事实
- 必须通过bi-temporal + time-sliced recall把"何时为真"变成硬约束

**三视角交点**：
- **认知科学**：episodic memory的时间是索引也是解释框架，支持recollection和reconsolidation
- **数据库**：bi-temporal分离valid_time（世界中何时为真）和transaction_time（系统何时记账）
- **知识图谱**：TKG让关系具备temporal validity，支持时间约束的动态图谱构建

**与其他维度交叉**：
- **时序×因果**：时间骨架是hard constraints，因果是soft inferences
- **时序×policy**：遗忘 = tombstone commit + 抑制，先validity再tombstone再decay
- **时序×压缩**：consolidation第一原则是不跨越变节点
- **时序×skill**：技能有"验证时间"，过期需要再验证而非线性衰减

**新增瓶颈：时间地基瓶颈**
- 时序归一化在fast path出错会导致所有上层view被污染
- 一次错误会反复被召回，很难靠LLM自纠正

## 八、关键结论

| 结论 | 说明 |
|------|------|
| Memory是外部状态 | 价值在于历史到决策的通道有效性 |
| 时序是结构维度 | 影响Ledger/Views/Policy三层，非附加metadata |
| Policy是瓶颈 | 非参数化上限往往受制于读写策略质量 |
| 证据而非裁决 | Memory提供证据，System 1负责决策 |
| 三层闭环 | Ledger→Views→Policy→Commit→Provenance实现可观测性 |
