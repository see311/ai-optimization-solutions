# LLM Gateway - 生产级架构设计

> 总结使用: MiniMax M2.5

## 核心定位

大模型场景下的专用 API 网关，统一收口所有模型调用请求，解决多模型多厂商散乱调用、无容错、难管控、成本不可控的问题。

## 三层架构

| 层级 | 职责 | 核心组件 |
|------|------|----------|
| 接入层 | 协议归一、鉴权限流 | 参数标准化、令牌桶限流、配额管理 |
| 决策层 | 智能路由、故障降级、负载均衡 | 路由规则引擎、健康监控、负载均衡器 |
| 出口层 | 协议适配、流式响应、日志指标 | 格式转换、SSE转发、链路追踪 |

## 四大路由策略

1. **基于能力路由**：任务类型 → 最擅长模型
2. **基于成本路由**：级联路由，便宜模型优先，质量不达标再升级
3. **基于延迟路由**：实时 P95 延迟统计，敏感请求优先路由到最快实例
4. **语义路由**：向量嵌入自动识别请求类型，无需人工定义规则

## 四层故障降级

```
同模型重试(指数退避) → 跨厂商切换 → 降级小模型 → 兜底(缓存/默认回答)
```

配合熔断器：闭合(正常) → 断开(连续失败) → 半开(探测恢复)

## LLM 负载均衡

区别于传统服务，需考虑请求处理时间差异巨大(1秒 vs 几十秒)：
- **加权负载均衡**：综合并发数、队列深度、预估处理时长
- **令牌吞吐量均衡**：按令牌处理量分配，避免长请求导致负载不均

## 语义缓存

将请求向量嵌入，查找相似度达标的历史请求命中缓存，大幅降低重复调用成本。
适用：常见问题、固定内容生成
不适用：实时资讯、创意写作

## 开源方案

| 类型 | 适用场景 |
|------|----------|
| 轻量网关 | 快速统一多模型接口 |
| 智能路由组件 | 聚焦成本优化 |
| 企业级网关 | 生产环境开箱即用 |

## 面试答题框架

三层架构 → 四大路由策略 → 四层故障降级 → 负载均衡 → 语义缓存 → 可观测性
