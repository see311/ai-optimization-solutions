# 一文讲清：为什么Agent = Model + Harness

## 核心公式

**Agent = Model + Harness**

- **Model**：提供智能能力
- **Harness**：所有不属于模型本身的代码、配置和执行逻辑

## Harness 的核心组成

| 组件 | 说明 |
|------|------|
| 系统提示词 | 定义 Agent 行为和约束 |
| 工具与技能 | 包括 MCP 等扩展机制 |
| 基础设施 | 文件系统、沙箱、浏览器等 |
| 编排逻辑 | 子 Agent 生成交接、模型路由 |
| Hook/中间件 | 上下文压缩、续写、Lint 检查 |

## Harness 的关键能力

1. **文件系统** - 持久化存储、跨会话状态、Agent 协作界面
2. **Bash/代码执行** - 通用工具，让 Agent 自助解决问题
3. **沙箱环境** - 隔离安全的执行环境，支持并行和按需扩展
4. **记忆与搜索** - AGENTS.md 记忆文件 + Web 搜索
5. **上下文管理** - 对抗 Context Rot，防止性能退化
6. **长时间执行** - Ralph Loop、规划、自验证机制

## 关键洞察

- 模型和 Harness 边界不清晰，但"非模型部分都是 Harness"这一定义区分度最高
- 同一模型在不同 Harness 下表现差异巨大（Top 30 → Top 5）
- Harness 不会消失，就像 Prompt 工程依然重要
- 未来趋势：模型可能吸收部分 Harness 能力，但工程价值永存
