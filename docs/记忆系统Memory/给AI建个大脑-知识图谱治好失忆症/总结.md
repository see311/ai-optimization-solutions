# 总结

## 核心问题
AI的"记忆系统"天然残缺：上下文窗口是沙漏，Session是纸杯——装多少漏多少。

## Ontology 解决方案
给AI建立**结构化的知识图谱**，用"实体+类型+关系"模式编织知识网络。

### 实体类型
| 类型 | 用途 |
|------|------|
| Person | 联系人、团队成员 |
| Project | 项目 |
| Task | 任务（含状态、优先级、阻塞关系）|
| Event | 日程事件 |
| Document | 文档 |
| Credential | 凭证（禁止明文存储）|

### 关系类型约束
- `has_owner`：Project/Task → Person，**多对一**
- `blocks`：Task → Task，**不能有环**

类型系统自动校验约束，类似TypeScript的类型检查，但检查的是业务逻辑。

## 核心价值
1. **可验证**：每一步规划都经过约束校验，违反约束会回滚
2. **可追溯**：图结构支持多跳查询
3. **可组合**：跨Skill共享状态的协议，Skill只需遵守"本体协议"

## 安全设计
`Credential` 类型的 `forbidden_properties` 强制禁止明文存储密码/密钥，从架构上杜绝密钥泄露。

## 适用场景
需要AI处理复杂项目、多角色协作、长期跟踪任务的场景。
