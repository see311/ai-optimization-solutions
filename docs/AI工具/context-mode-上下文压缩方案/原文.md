# context-mode：GitHub 2 天暴涨 13k

**context-mode** 是一个 MCP Server，专门解决 AI 编程 Agent（Claude Code、Gemini CLI、VS Code Copilot 等）在长对话中"上下文爆炸"的问题。

简单说：它把原本塞进上下文窗口的原始数据（命令输出、文件内容、日志）拦截下来，压缩存进 SQLite，模型只看到结果摘要。

**GitHub 数据：**
- 总 Stars：**13,226** ⭐
- 今日新增：**+276** （近期增长迅猛，上线约 2 天即达 13k+）

# 解决什么问题

所有用 AI 编程助手的人都会遇到这个场景：

> 用了 30 分钟，Agent 开始"忘记"之前做了什么。
> 它说"我刚才改了这个文件"——但其实已经忘了。
> 因为上下文满了，它开始"压缩"对话，然后丢失关键信息。

context-mode 解决了这四个问题：

**1. 上下文污染**
- 一个 Playwright 快照 = 56 KB
- 20 条 GitHub issues = 59 KB
- 30 分钟对话后，40% 上下文是垃圾数据

**2. 对话压缩后失忆**
- 模型压缩上下文时，删掉的是"它正在改什么文件"
- 下一次对话要重新花时间理解项目

**3. 输出 token 浪费**
- Agent 写一堆废话解释自己在干什么
- 实际上只需要结果

**4. 跨平台割裂**
- 用了 Claude Code，又用 Gemini CLI
- 每个工具各自为政，没有统一上下文管理

# 值得关注的点

## 1. 核心数据：98% 上下文压缩

这是官方给出的核心指标：
```
# 之前：47 次 Read() = 700 KB
ctx_execute("javascript", `...`); // = 3.6 KB
```
从 700 KB 压缩到 3.6 KB，降幅 99.5%。实际使用中，平均节省 98% 上下文空间。

这个数字是怎么来的？
- 工具输出被截断，只保留摘要
- 重复读取同样文件的结果被缓存
- 模型真正需要知道的是"结果是什么"，不是"输出了什么"

## 2. "Think in Code"哲学：让 AI 编程，而不是让 AI 阅读

context-mode 的另一个核心理念：

> **Stop treating the LLM as a data processor. Treat it as a code generator.**

比如要统计一个目录里所有 TypeScript 文件的行数：

**传统方式（浪费上下文）：**
让 Agent 读 47 个文件 → 700 KB 进入上下文

**context-mode 方式：**
让 Agent 写一个脚本，脚本执行后只输出结果 → 3.6 KB

```javascript
// Agent 发送这段代码，它不会被完整存入上下文
// 只有 console.log 的结果会被记录
const files = fs.readdirSync('src').filter(f => f.endsWith('.ts'));
files.forEach(f => console.log(f + ': ' + 
 fs.readFileSync('src/'+f,'utf8').split('\n').length + ' lines'
));
```

这不只是节省 token——它改变了 Agent 的工作方式，从"读取一切"变成"执行+获取结果"。

这种策略的护城河：
- 不抢用户已有工作流
- 平台越多，迁移成本越高
- 平台方有动力推广（因为这让他们的产品更好用）

# 个人启发

## 对普通开发者的意义

如果你用 Claude Code 或者 Copilot：
1. **先跑一次 `ctx stats`**，看看自己浪费了多少上下文
2. **安装 context-mode** （Claude Code 用户直接 `/plugin marketplace add mksglu/context-mode`）
3. 开始养成"让 AI 执行，而不是让 AI 阅读"的编程习惯

安装之后，你会发现同样一个任务，模型的响应速度变快了（因为上下文小了），长对话后期的"失忆"现象也消失了。

## 对创业者的启示

context-mode 的商业模式目前是**免费开源**，但它的增长策略值得学习：

- **定位在"中间件"层**：不做一个新的 AI 编程工具，而是让所有工具变强
- **用数据说话**：98% 压缩率，一个数字胜过大段描述
- **平台锁定**：支持的平台越多，用户粘性越高

如果要做类似方向，可以考虑：
- 收费层：团队上下文管理、跨平台同步
- 企业层：合规审计（企业需要知道 AI 改了什么）
- 数据层：分析用户的上下文使用模式，做优化建议

---

**总结：context-mode 解决了一个用 AI 编程的人早晚都会遇到的问题——上下文不够用。它用 Hook 系统嵌入现有 Agent，不改变用户习惯，用数据（98%）说话，增长策略聪明。值得每个用 AI 写代码的人装一个试试。**
