# RAG落地核心难点

## 核心观点

RAG 真正的难点从来不是搭建基础 Demo，而是**落地后持续调优达到业务标准**。整个链路中每个环节都可能成为瓶颈，各环节相互关联影响，没有捷径可走。

## 三大核心难点

### 1. 文档预处理

**问题本质**：文档预处理是整个系统的基础根基，根基没打牢，后续所有优化都是白费功夫。

**常见挑战**：
- PDF 表格、双栏布局、多层嵌套排版内容难以正确解析
- pypdf 等基础工具只提取文本信息流，不适配复杂排版
- 表格数据被拆解成杂乱单行文字，行列关联关系丢失
- 扫描版文档需要 OCR、含图片文档无法提取关键信息

**解决方案**：
- 使用 pdfplumber 处理表格文档
- 使用 unstructured 库适配不同文件格式
- 高价值文档可用多模态模型识别 PDF 截图
- 文档预处理代码体量往往超过 RAG 核心业务逻辑

### 2. 检索质量调优

**问题本质**：向量召回不准直接决定了整个 RAG 系统的效果上限。

**常见挑战**：
- Chunking 划分不合理，用户问题与知识库内容无法语义匹配
- 用户口语化提问与文档正式表述存在语义差异
- 向量检索对精确词汇（型号、专有名词、行业缩写）匹配效果差

**解决方案**：
- 对 Query 进行语句改写
- 为每个 chunk 预生成多种常见提问句式
- 采用混合检索模式：向量检索 + BM25 关键词检索

### 3. 效果评估困难

**问题本质**：无法快速判断调整后效果是变好还是变差，找不到明确优化方向。

**评估维度**：

| 维度 | 说明 |
|------|------|
| **检索评估** | Hit@K 指标，批量自动化运行，快速判断检索瓶颈 |
| **忠实度** | 答案是否基于检索内容，无编造 |
| **答案相关性** | 回答是否匹配用户问题 |
| **上下文召回率** | 检索内容能否覆盖全部知识点 |

## 面试回答框架

回答此类问题，核心要点是**有逻辑分层、搭建清晰框架**，不要零散堆砌知识点。建议采用"三大难点 + 解决思路"的框架来组织答案。
