# 吃透Agent三大范式总结

## 核心要点

### 三大范式定位差异

| 范式 | 定位 | 解决的问题 |
|------|------|-----------|
| **ReAct** | 独立执行范式 | 任务执行灵活性 |
| **Plan-and-Execute** | 独立执行范式 | 长流程可控性 |
| **Reflection** | 非独立增强机制 | 输出质量严谨性 |

### ReAct范式
- **核心逻辑**：思考→行动→观察→再思考，单步迭代
- **优势**：轻量易落地、灵活应变、链路透明
- **短板**：长任务易跑偏、token线性增长
- **适用场景**：简单问答、轻量化工具调用、步骤少的任务

### Plan-and-Execute范式
- **核心逻辑**：规划与执行解耦，先全局规划再分步落地
- **优势**：长任务可控、强弱模型搭配降本70-90%
- **短板**：灵活度不足、架构复杂
- **适用场景**：长流程调研、多环节任务、复杂文书生成

### Reflection范式
- **核心逻辑**：生成→评估→改进三步循环
- **作用**：质量校验与修正buff，不可独立运行
- **适用场景**：代码生成、法律合规、医疗金融等高严谨性场景

### 进阶机制
- **动态Replan**：解决计划僵化，自适应中途变化
- **Reflexion**：错题本机制，跨任务经验沉淀

### Token消耗对比
- ReAct：五步约30K token（线性增长）
- Plan-and-Execute：五步约14.5K token（节省50%+）
- 叠加Reflection：增加30%-100%

### 选型准则
1. 简单轻量任务 → ReAct
2. 复杂长流程 → Plan-and-Execute
3. 高严谨要求 → 叠加Reflection

### 面试核心答案
1. Reflection与ReAct/Plan-and-Execute**不是同层级**，是增强机制
2. ReAct边想边干，Plan-and-Execute先想全再干
3. Reflection执行后反思，生成-评估-改进闭环
