# Codex 数据智能体 - 六层上下文架构

> 总结使用: MiniMax M2.5

## 背景痛点

OpenAI 内部 600PB 数据分布在 7 万个数据集中，工程师面临：
- 同样叫"活跃用户"，不同表口径完全不一样
- 选错表 = 数天努力白费
- 正确 SQL 可能 180+ 行，错一个连接条件就前功尽弃

## 六层上下文架构

| 层级 | 内容 | 作用 |
|------|------|------|
| 基础元数据 | 表结构、列类型 | 数据图谱骨架 |
| 人工标注 | 领域专家编写的表/列描述 | 捕捉意图、业务含义 |
| Codex 增强 | 代码级定义推导（值唯一性、更新频率、数据范围） | 理解表构建差异 |
| 机构知识 | Slack、Google Docs、Notion | 产品发布、可靠性事件、指标定义 |
| 学习进化 | 持久记忆（用户纠正、经验积累） | 可全局或个人专属 |
| 运行时上下文 | 实时查询数据仓库 | 补充最新数据 |

## 关键创新：离线+在线协同

**离线流程**（每天凌晨）：
1. 扫描昨天数据表使用轨迹
2. Codex 解读代码逻辑，衍生业务语义
3. 融合成统一"知识图谱"
4. 向量嵌入存入高速检索库

**在线流程**：
- 快速问题 → 闪电检索离线知识
- 需要最新数据 → 实时查询数据仓库
- 两者协同，秒级响应

## 实战经验

1. **限制数据表访问**：智能体能访问完整数据集会迷失，需要限制范围减少歧义
2. **让智能体自主决策**：僵化的系统提示词适得其反，把实现方式交由智能体决定更稳健
3. **代码比元数据更准确**：查询历史 + Codex 爬取代码库，能捕获从未在 SQL 或元数据中浮现的业务意图
