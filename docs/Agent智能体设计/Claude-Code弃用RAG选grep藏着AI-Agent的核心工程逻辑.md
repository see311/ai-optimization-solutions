# Claude Code弃用RAG选grep，藏着AI Agent的核心工程逻辑

上周，一个AI Agent岗的朋友，跟我分享了他的面试经历，全程充满了意外和冲击。不同于以往"手写Transformer""讲解RLHF原理"的常规考题，面试官没有纠结于复杂的模型理论，而是在黑板上画了一个简单的架构图，抛出了一个看似反直觉的问题："Claude Code的代码搜索功能，为什么不用当下热门的RAG技术，反而选择了几十年前就存在的grep命令？你觉得这个选择是对是错？"

朋友当场就愣住了。他说自己用Claude Code写了半年代码，每天都在享受它高效的代码搜索能力，却从来没有想过背后的技术选型逻辑。慌乱之下，他只能从"grep运行速度快""向量数据库维护麻烦"这些表面角度回答，面试官全程面无表情，最后只说了一句："你的回答，没有触及本质。"

说实话，这个问题问得非常"狠"，也非常有水平。它看似是在考察一个工具的选择，实则直指2026年AI Agent领域最核心的工程取舍：搜索的确定性与智能化如何平衡，模型的推理能力边界在哪里，以及成本与效果之间那道极窄的平衡线该如何把握。

很多做AI Agent开发的人，都陷入了一个误区，认为越"高级"的技术越好，RAG作为当下语义搜索的主流方案，自然被默认为代码搜索的最优解。但Claude Code的选择，恰恰打破了这种固有认知，也给所有AI Agent从业者上了一堂深刻的工程实践课。今天，我们就从这个面试题出发，一步步拆解背后的逻辑，搞懂为什么grep能在代码搜索场景下，打败风头正劲的RAG。

## 一、先澄清一个事实：Claude Code早期用过RAG，后来全删了

在深入分析之前，我们先把事实摆清楚。很多人可能会觉得，Claude Code选择grep是因为团队不熟悉RAG技术，或者为了节省开发成本，但事实恰恰相反——Claude Code的创建者Boris Cherny，在多个公开场合亲口确认，这款工具的早期版本，不仅用过RAG，还搭建了完整的向量数据库架构。

在X（原Twitter）上，Boris Cherny曾直接发文："Early versions of Claude Code used RAG + a local vector db, but we found pretty quickly that agentic search generally works better." 翻译成通俗的话就是，Claude Code的早期版本，老老实实地搭建了向量数据库，做了代码片段的索引，跑通了语义搜索的全流程。但团队很快就发现，Agentic Search（即让模型自己驱动grep和glob命令进行动态搜索）的效果，远比RAG更好。

在Pragmatic Engineer的采访中，他说得更彻底："Plain glob and grep, driven by the model, beat everything." 意思就是，由模型驱动的、最基础的glob和grep命令，打败了所有更"高级"的搜索方案，包括RAG。

这个决策并不是Boris Cherny的拍脑袋之举，而是基于长期的观察和实践。他在Meta工作期间，曾观察到一个非常有趣的现象：Instagram的工程师们，平时依赖IDE里的"click-to-definition"（点击跳转定义）功能查看代码，但当这个功能崩溃后，所有人都不约而同地回退到了手动grep搜索代码的方式。更意外的是，这些工程师的工作效率，并没有因为工具的"降级"而出现明显下降。

Boris Cherny把这种现象称为"回归均值"，那些被过度设计的智能搜索功能，看似便捷高效，实则并没有我们想象中那么不可替代。尤其是在代码搜索这个场景下，开发者对"精准找到目标内容"的需求，远高于"搜索过程是否智能"的需求。而grep的核心优势，恰恰就是"精准"。

可能有人会质疑，这只是Boris Cherny一个人的直觉，不足以支撑这样的技术选型。但2026年5月的一篇最新论文，彻底验证了他的判断，也让整个AI工程界重新审视grep这个"老工具"的价值。

## 二、论文实锤：2026年最新研究，grep在代码搜索上碾压RAG

2026年5月14日，一篇题为"Is Grep All You Need? How Agent Harnesses Reshape Agentic Search"的论文，正式挂在了arXiv平台上。这篇论文的研究团队，做了一个极其严谨的控制变量实验，目的就是对比grep和RAG（向量检索）在代码搜索场景下的表现。

实验的设置非常细致：研究团队选取了LongMemEval数据集中的116个代码搜索问题，涵盖了函数定义查找、变量引用定位、API调用查询等常见场景；同时，在Claude Code、Codex、Gemini CLI三个主流AI Agent框架上分别进行测试，确保实验结果的跨框架稳定性。

实验结果出来后，让很多深耕AI搜索领域的开发者感到意外甚至沉默：在精确匹配场景下，grep的平均准确率显著高于向量检索，而且这个结论在三个框架上都保持一致。也就是说，不管是Claude Code还是Codex、Gemini CLI，用grep做代码搜索，效果都比RAG更好。

更值得注意的是，Claude Code官方团队，也在其开源项目的README文件中明确写道："Claude Code's 'agentic search' is really just glob and grep, and it outperformed RAG." 相当于官方直接承认，他们弃用RAG、选择grep，是经过实践验证的最优解。

## 三、核心原理：不是工具搜得好，是AI会"问问题"

要理解grep为什么能在代码搜索上干掉RAG，我们首先要分别搞清楚，传统RAG和Claude Code的搜索方式，到底有什么不同。这两者的区别，本质上是"被动接收答案"和"主动探索答案"的区别。

传统RAG的工作方式，可以理解成一个"提前整理好答案的助手"：第一步，把整个代码库提前切成一个个小的代码片段；第二步，用嵌入模型把每个代码片段转换成向量，存储到向量数据库中；第三步，当开发者提出搜索问题时，系统会把问题也转换成向量，和向量数据库里的所有向量做相似度匹配，找出Top-K个最相似的代码片段，塞进AI的上下文里。

这种方式看起来很聪明，但它的致命缺陷恰恰就藏在这个"聪明"里——在代码搜索场景下，"语义相似"不等于"精准匹配"，而开发者要的，往往是后者。

grep不需要做任何向量转换，也不需要提前建索引，只要给出正确的关键词，它就能直接在整个代码库中搜索包含该关键词的所有内容。在代码搜索这个场景里，精确性本身就是一切。

更关键的是，Claude Code的做法，并不是简单地用grep替换RAG，而是把搜索的主动权，完全交给了AI本身。它的核心逻辑是：让LLM自己决定"该怎么搜"，而不是让系统提前替它"筛好答案"。

这就像一个有多年经验的资深开发者，在查看陌生代码库时的操作：先凭经验搜一个模糊的关键词，看看大致的范围，再根据找到的线索逐步缩小范围，最终精准定位到目标内容。而传统RAG，相当于有人提前替你筛好了一堆"可能相关"的内容，但你不知道这些内容是不是你真正需要的。

那篇2026年5月的最新论文，用一句话总结了grep在代码场景下的核心优势："lexical precision matters in code search." 在代码搜索中，词法精确性的重要性被严重低估了。

## 四、深入拆解：RAG在代码搜索中的三个致命短板

### 短板一：代码一变，索引全废，维护成本高到无法承受

RAG的核心依赖是"向量索引"，而索引无法实时更新。代码库是动态变化的，索引根本无法做到实时更新。而grep不需要任何索引，永远能获取到最新的代码内容。

### 短板二：噪声过多，语义漂移导致模型被误导

RAG的语义搜索，很容易出现"语义漂移"，返回大量无关的内容。语义漂移带来的噪声，会误导模型的推理，进而生成错误的代码。

### 短板三：剥夺模型的主动探索能力，推理能力反而下降

RAG看似把搜索环节做"智能"了，实则剥夺了模型的主动探索和验证能力。RAG是"喂给模型答案"，而grep方案是"让模型自己找答案"。对于AI Agent来说，主动探索和验证的能力，远比被动接收答案更重要。

## 五、客观看待：grep方案也有无法回避的代价

### 代价一：Token消耗大幅增加，成本更高

grep方案的Token消耗，比RAG方案高30%-60%。

### 代价二："猜词"门槛高，依赖关键词准确性

如果不知道正确的关键词，grep就搜不到任何结果。

### 代价三：速度与并发瓶颈，大型代码库表现不佳

对于100万行以上的monorepo，一次全量grep搜索可能需要几十秒。

### 代价四：缺乏结构化理解，无法识别代码逻辑

grep把代码当成纯文本处理，完全不理解代码的结构化逻辑。

## 六、回归面试题：面试官真正想问的，是工程取舍思维

grep和RAG之间，从来不是"非此即彼"的选择，而是"场景适配"的选择。不同的搜索场景，最优解完全不同：

1. 需要精确匹配还是语义相似匹配？
2. 代码库的更新频率如何？
3. 上下文预算有没有压力？

2026年，AI Agent的工程选型，已经不再是"哪个方案更高级"的炫技，而是"在什么条件下，哪个方案的总代价最小"的理性决策。

## 写在最后：AI Agent的核心，是"主动解决问题"的能力

AI Agent的本质，不是一个被动接受信息的工具，而是一个能主动探索、主动验证、主动追问的任务执行者。它的核心能力，不是"能用多高级的技术"，而是"能精准解决问题"。

RAG是"给你一份别人替你筛好的答案"，而grep是"让你自己去问问题"。AI Agent的价值，不在于被动接收答案，而在于主动探索答案，这才是Claude Code选择grep的本质。
