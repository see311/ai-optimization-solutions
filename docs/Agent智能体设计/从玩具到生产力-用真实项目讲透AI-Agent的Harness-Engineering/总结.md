# 从玩具到生产力：用真实项目讲透 AI Agent 的 Harness Engineering

## 核心要点

### 一、Harness Engineering 是什么？

**定义**：Harness 不是某条提示词、某个工具，也不是多写几份文档。它是一整套把大模型纳入工程体系的**控制面**：

- 如何提供唯一的真相源？
- 如何约束执行边界？
- 如何接入业务能力（Capability）？
- 如何观测、调试运行状态？
- 如何让产出可验证、可回归？

**与传统软件工程的本质区别**：
- 传统软件工程管的是**「确定性」**——人类有常识但容易手滑
- Harness Engineering 管的是**「非确定性」**——大模型是概率引擎，可能调错Tool、可能幻觉暴走

### 二、架构坐标系：Harness 的边界

用两个坐标轴界定 Harness Engineering 的边界：

| 坐标轴 | 两端 |
|--------|------|
| X轴（执行流路由） | 静态预设 ↔ 动态自主 |
| Y轴（状态与上下文） | 隐式内部 ↔ 显式外部 |

**四象限没有绝对优劣，只有场景适配**：
- 【象限三：无状态链】LLM当纯函数，低成本高吞吐
- 【象限二：提示词驱动】如AutoGPT，开发成本低但长链路容易失控
- 【象限四：传统管道】模型被动调用，适合流程固定场景
- 【象限一：Harness Engineering】外部Harness负责状态隔离与沙盒校验，适合企业级复杂场景

### 三、避坑指南：识别"伪 Harness"与"劣质 Harness"

**伪 Harness（根本不是 Harness）**：
- **"软约束"陷阱**：Prompt里写5000字、几十条DO NOT——这只是"口头嘱咐"
- **"军火库"陷阱**：一股脑给Agent塞20个API让模型自己挑

**劣质 Harness（是 Harness 但质量差）**：
- **"盲打"陷阱**：暴力死循环重试，一报错就塞回模型继续试
- **"官僚主义"陷阱**：生搬瀑布流，强制先输出万字设计文档

**好的 Harness 应该什么样**：
- 前置验证（Evaluator 沙盒）：单测失败时强制复述"核心目标"
- 最小真相源（Spec is Truth）：轻量状态机文档，跨天无损恢复上下文
- 物理门禁（Checkpoint Before Execute）：模型破坏环境前必须拿授权

### 四、工程师角色迁移

**核心迁移**：从"亲手写出每一行代码" → "定义目标、卡住边界、掌控节奏、验收结果"

**真正强的 Harness 使用者**：
- 知道什么时候不必盯细节
- 知道什么时候必须下潜检查
- 日常不干涉怎么写函数，但关键时刻一定接管

**关键接管时刻**：
1. 架构主线可能被污染时
2. 阶段目标开始漂移时
3. 运行时日志暴露系统性异常时
4. 模型把"阶段完成"误报成"全局完成"时

### 五、sdd-riper-one-light 实施层骨架

基于**契约式设计（Design by Contract）**，四个控制点对应三大契约：

| 契约 | 作用 | 机制 |
|------|------|------|
| 前置断言（Pre-conditions） | 拦截输入端失控 | 强制 Checkpoint + Restate First |
| 后置断言（Post-conditions） | 拦截输出端幻觉 | 闭环回写（Reverse Sync） |
| 不变式（Invariants） | 对抗跨周期状态腐烂 | 维护最小真相源（Spec is Truth） |

### 六、实操 SOP：8 阶段流程

| 阶段 | 给模型的输入 | 要求返回 | 控制动作 |
|------|-------------|----------|----------|
| 1. 目标收敛 | 先读文档，不准写代码 | 需求复述、主线判断 | 先纠偏，再放行 |
| 2. 状态恢复 | 先读 Spec/Handoff | 已完成项、未完成项 | 用外部真相源恢复 |
| 3. 上下文装配 | 不整包投喂，只给索引 | 最小上下文清单 | 按需补充，避免爆 Context |
| 4. 任务分块 | 这一轮只做一个小段 | 1-3个动作、风险、验证 | 只批准当前轮次 |
| 5. 链路设计 | 先判断走什么模式 | 执行模式和装配方案 | 先定路线，不盲改Prompt |
| 6. 执行前校准 | 先别改代码，先Checkpoint | 理解、目标、动作、风险 | 对齐后再 Approval |
| 7. 外部验证 | 不接受"我觉得好了" | 基于日志、测试的事实判断 | 用证据而非主观决策 |
| 8. 回写交接 | 暂停前必须回写 | 完成项、偏差、残留 | 给下一轮留恢复点 |

### 七、盯住"三层目标"

长链路任务最危险的不是模型不会做，而是它绕过当前阶段目标冲向"总目标"。

**三层目标同时盯**：
1. **总核心目标**：整个项目/大阶段要完成什么
2. **阶段性核心目标**：当前这几轮只收敛哪个主问题
3. **本轮动作目标**：这一轮具体只做哪1-3个动作

**判读原则**：阶段完成 ≠ 全局完成

### 八、偏航的 4 个信号

1. 开始绕过阶段目标，直接谈总目标
2. 开始跳过中间产物，直接声称要改代码
3. 开始用主观语气替代客观证据
4. 开始混淆阶段完成和全局完成

**纠偏关键**： Harness 的价值不在于"一开始别跑偏"，而是**持续性的控制动作**——它不是一开始就错，而是做着做着慢慢偏。

### 九、行业印证

- **OpenAI Engineering**：放弃巨型Prompt，把代码仓库作为记录系统
- **Anthropic Labs**：用强制 Context Resets + 独立 Evaluator Agent 提供外部客观真相
- **deer-flow**：Super Agent Harness——把模型"大脑"与执行环境物理隔离

**底层哲学**：想释放大模型的生产力，第一步是先建好约束和轨道。
