# ArrowJS 发布 1.0 版，转型为"代理时代"的首个 UI 框架

> 原文：InfoQ｜作者：Daniel Curtis｜译者：平川
> 原文链接：https://www.infoq.com/news/2026/06/arrowjs-v1-agentic/
> 发布时间：2026-06-28

由 FormKit 和 AutoAnimate 创始人 Justin Schroeder 创建的轻量级响应式 UI 库 **ArrowJS** 已经发布 1.0 版本，并被重新定位为 **"代理时代"的首个 UI 框架**。在作为公开实验项目运行约三年后，ArrowJS 1.0 稳定版开源，其代码库已经迁移至 GitHub 上的 `standardagents` 组织下，最新补丁版本于 2026 年 4 月更新至 v1.0.6。

---

## 核心理念与设计哲学

该框架完全基于开发者和大型语言模型都已经熟知的平台基础组件构建，即 **JavaScript 模块、带标签的模板字面量和 DOM**。它不使用 JSX，没有编译器，也不需要构建步骤，核心运行时文件大小不到 5KB。

其团队声称，该框架的性能基准测试结果与 Vue 3 相当。整个框架仅基于三个函数：`reactive`、`html` 和 `component`。其维护者指出，该框架的全部文档内容仅占 20 万 Token 上下文窗口的不到 5%，这正是其宣称对智能体友好的核心卖点。

> **关键设计目标：** 让 AI 代理能够直接生成可运行的 UI 代码，无需学习复杂的框架语法和构建工具链。

---

## 1.0 版本核心特性

### WASM 沙箱（核心新增）
`@arrow-js/sandbox` 包在 QuickJS WebAssembly realm 内运行组件逻辑，同时仍然渲染真实的内联 DOM，从而允许应用程序在不使用 iframe 或 eval 的情况下执行不可信的、由代理生成的代码。

这解决了以前无法解决的难题：**如何安全地运行 AI 生成的不可信的界面**。

### 分层架构
围绕核心功能，本次发布还在不同的层上提供了多个包：
- `@arrow-js/core` — 核心运行时（响应式 + 渲染 + 组件）
- `@arrow-js/framework` — 异步组件支持
- `@arrow-js/ssr` — 服务器端渲染
- `@arrow-js/hydrate` — 客户端水合
- `@arrow-js/sandbox` — WASM 沙箱安全执行

### 代理技能包
该团队还提供了一个代理技能，可通过 `npx @arrow-js/skill` 安装。该技能可以指导编程代理将 Arrow 添加到当前已有的项目中。

## 技术架构

### 响应式系统
ArrowJS 采用细粒度响应式系统，在模板表达式中追踪依赖，无需虚拟 DOM diff 过程。

- 使用 `reactive()` 包装对象或表达式，创建可观察数据结构
- 状态变更时自动触发 UI 更新
- 只有在模板中以函数形式引用的属性才会被追踪（细粒度更新）

```javascript
import { reactive, html } from '@arrow-js/core';

const state = reactive({
  user: { name: 'Alice', age: 30 },
  settings: { theme: 'dark' },
});

// 只有 user.name 被追踪，settings.theme 的变化不会导致重渲染
const ui = html`
  <p>Hello, ${() => state.user.name}!</p>
`;
```

### 模板渲染
使用 JavaScript 模板字面量（`html` 标签函数），其中函数表达式表示响应式绑定，实现细粒度更新而无需重渲染整个组件。

### 性能表现
性能基准测试显示 ArrowJS 与 Vue 3 和 Solid 等成熟框架相当：
- `01_run1k` 基准测试：ArrowJS 43.0ms / Vue 42.1ms / Solid 31.7ms
- 关键场景更新性能约 20.2ms，与行业领先者持平

## 社区反响与争议

### 正面评价
- 极简主义设计，仅三个辅助函数即可构建完整 Web 应用
- 零依赖、零构建步骤，上手快
- 对 AI 代理友好，降低代码生成的出错率
- WASM 沙箱解决了 AI 生成代码的安全执行问题

### 批评与不足
在 GitHub 的一场讨论中，一位已经发布过完整应用的开发者报告了以下问题：
1. 在监听器内部修改状态时会出现错误
2. 除非每个项目都带有唯一键，否则映射数据会引发重渲染故障
3. 响应式对象嵌套在其他响应式对象内部时存在陷阱
4. 缺少生命周期钩子、事件修饰符和 DOM 引用（DOM refs）

Schroeder 表示同意，他也认为值得添加 DOM 引用和一个基本的 mounted 钩子。

> 有评论者认为："Arrow 实际上是在鼓吹只使用原生 JavaScript，却通过伪装成框架来误导用户。"

## 与主流框架的对比

与 React 和 Vue 相比，ArrowJS 以牺牲深厚的组件生态系统和惯用规范为代价，换取了原始的简洁性和与平台的紧密结合。

| 特性 | ArrowJS | React | Vue |
|------|---------|-------|-----|
| 核心体积 | <5KB | ~42KB | ~33KB |
| JSX/模板语法 | 模板字面量 | JSX | Vue Template |
| 构建步骤 | 不需要 | 需要 | 需要 |
| 响应式原理 | 细粒度依赖追踪 | 虚拟 DOM diff | 响应式系统 |
| 生态系统 | 小（新兴） | 庞大 | 庞大 |
| AI 友好度 | 高（原生语法） | 中（需学习JSX） | 中（需学习模板语法） |

## 快速开始

### 安装
```bash
# 核心运行时
npm install @arrow-js/core

# 完整栈（含 SSR 和水合）
pnpm add @arrow-js/core @arrow-js/framework @arrow-js/ssr @arrow-js/hydrate
```

### 浏览器直接使用（无需构建）
```html
<script type="module">
  import { html, reactive } from 'https://esm.sh/@arrow-js/core'
</script>
```

### 示例：计数器组件
```javascript
import { component, html, reactive } from '@arrow-js/core'

const Counter = component(() => {
  const count = reactive(0)
  
  return html`
    <div class="counter">
      <button @click=${() => count.value--}>-</button>
      <span>${count}</span>
      <button @click=${() => count.value++}>+</button>
    </div>
  `
})

// 挂载到 DOM
Counter().mount(document.getElementById('app'))
```

## 总结

ArrowJS 1.0 标志着前端框架领域的一个新方向——**为 AI 代理而设计**。它的极简设计（三个核心函数、零构建步骤、<5KB 体积）和 WASM 沙箱特性，使其特别适合由 AI 生成和维护的界面场景。

虽然生态系统尚不成熟，与 React/Vue 等主流框架相比缺少大量工具和组件，但它代表了代理时代前端开发的一种新思路：与其让 AI 学习复杂的人类框架，不如设计对 AI 更友好的框架。
