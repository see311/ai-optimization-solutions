# 浏览器自动化：从GUI到OpenCLI - 核心要点

## 核心观点

传统的 UI 自动化（点击按钮、填写表单）不稳定且难以维护。OpenCLI 提出了一种更优雅的解决方案：**不操作界面，直接复现底层 API 请求**。

## AI Agent 探索工作流

| 步骤 | 操作 | 工具 |
|------|------|------|
| 1 | 打开浏览器 | browser_navigate |
| 2 | 观察页面元素 | browser_snapshot |
| 3 | 首次抓包 | browser_network_requests |
| 4 | 模拟用户交互 | browser_click + browser_wait_for |
| 5 | 二次抓包 | browser_network_requests |
| 6 | 验证 API | browser_evaluate |
| 7 | 编写适配器 | YAML / TypeScript |

## 五级认证策略

```
Tier 1: public      → 公开 API，直接 fetch
Tier 2: cookie     → 需要 Cookie（最常见）
Tier 3: header     → 需要 Bearer/CSRF header
Tier 4: intercept  → 需要拦截 Store Action
Tier 5: ui         → 最后手段，UI 自动化
```

## 适配器开发

- **TypeScript**：`evaluate` 步骤 → 动态注册
- **YAML**：纯声明式（navigate + tap + map + limit）

## 未来趋势

> 过去的软件竞争界面，未来的软件竞争可调用性。

未来的 SaaS 不仅是给人用的，更要被 Agent 理解、调用和验证。可调用性将成为新的竞争维度。
