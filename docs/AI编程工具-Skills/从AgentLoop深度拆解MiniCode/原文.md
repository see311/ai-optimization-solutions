# 从Agent Loop深度拆解Mini Code，看懂Claude Code极简内核实现逻辑

## 前言

当下AI代码智能体已经成为开发领域的热门赛道，Claude Code凭借强大的代码理解，工程编辑和自主迭代能力，成为开发者日常编码，项目重构，问题排查的得力助手。很多开发者都好奇，这类专业代码智能体的底层运行逻辑究竟是什么，能不能用轻量化项目复刻其核心能力。

Mini Code作为Claude Code的最小化还原项目，没有冗余的业务封装，保留了代码智能体最核心的运行骨架，尤其在Agent Loop循环机制的设计上，浓缩了工业级代码智能体的设计思想。读懂Mini Code的Agent Loop，就能通透理解Claude Code这类代码智能体的运转底层逻辑，也能为自研私有化代码智能体提供完整的设计参考。

本文将从执行机制，收尾清理机制，上下文分层压缩机制三大核心维度，完整拆解Mini Code的设计思路，梳理每一处细节设计的底层考量，总结可落地的工程化设计思想，带大家真正吃透代码智能体循环架构的精髓。

## 一、认知重构，代码智能体不是简单模型调用

很多初学者对AI代码智能体存在认知误区，认为智能体就是大模型搭配工具函数，模型返回工具调用指令，程序执行对应函数，再把结果回传给模型，循环往复即可完成任务。

但真实工业级代码智能体的设计远没有这么简单。模型的响应形态从来不是单一的工具调用，还包含思考过程，进度说明，最终回复，空响应，超长输出截断等多种场景。同时一次交互回合结束后，还要处理状态回收，会话持久化，权限隔离，UI状态同步等配套工作。更关键的是，长期对话会不断累积上下文，token占用持续走高，若没有合理的上下文治理策略，智能体会很快因上下文溢出瘫痪失效。

Mini Code的核心价值，就是把这些工程化细节全部落地，构建了一套完整可运行的Agent Loop状态机。它的循环体系围绕三大支柱搭建，分别是execute执行机制，cleanup收尾清理机制和compact上下文压缩机制。三者各司其职又相互配合，共同支撑起智能体长时间，高稳定，低损耗的自主运行能力。

## 二、execute执行机制，拆解一次完整的智能体交互流程

execute机制是Agent Loop的核心执行单元，负责处理大模型返回的所有响应内容，区分不同响应类型并做标准化解析，批量调度工具执行，捕获异常并统一封装结果，同时处理超长内容截断，空响应自愈，人工介入等待等特殊场景。

整个执行流程遵循固定的分层逻辑，先解析模型附加文本信息，再批量处理工具调用请求，完成工具执行后统一整理会话消息，最后判断是否需要进入下一轮循环或是等待用户输入。整套流程实现了模型响应全场景覆盖，让每一种输出都有对应的处理逻辑。

### 2.1 模型多类型响应分层处理

大模型单次返回的响应包含多种组合形态，Mini Code没有采用一刀切的处理方式，而是划分出五大类核心响应结构，分别定制处理逻辑。

第一类是thinking block思考块。这是模型内部推理过程的结构化输出，Mini Code会将其单独封装为assistant_thinking角色消息存入会话历史。思考块可以和任意响应形态组合搭配，既能放在普通最终回复，进度提示文本之前，也能和工具调用并行存在。它仅做记录留存，不决定循环终止，后续流程依旧由进度文本，普通回复或工具调用主导。

第二类是progress进度文本。这类文本代表模型尚未完成任务，只是向用户同步当前工作进度，并非最终答案。Mini Code识别到进度文本后，会自动追加一条user角色的接续提示词，内容为

```
Continue immediately from your <progress> update with concrete tool calls, code changes, or an explicit <final> answer only if the task is complete.
```

这条提示词的核心作用是强制模型跳出单纯的文字描述，必须落地到具体动作，要么调用工具，要么修改代码，只有任务彻底完成才能给出最终回复，避免智能体停留在空泛的进度说明中停滞不前。

第三类是普通assistant文本。这是智能体任务完成的核心标志，当模型无进度提示，无工具调用，仅返回纯文本内容时，Mini Code会将其作为最终输出，追加assistant角色消息，直接终止本轮Agent Loop，用户即可获取完整结果。值得注意的是，单纯的工具返回结果永远不会判定任务结束，工具输出只是给模型参考的中间数据，必须由模型给出普通文本回复，才算真正完成一轮交互。

第四类是tool calls工具调用。这是代码智能体最核心的动作形态，存在三种常见组合，进度文本加工具调用，普通文本加工具调用，纯工具调用无附加文字。Mini Code会先解析并存入前置的文本消息，再统一批量执行所有工具调用请求。

第五类是特殊异常响应，包含截断响应和空响应两种。当模型因max_tokens限制或主动暂停被截断，且内容为空时，系统会判定为可恢复中断，追加提示词告知截断原因并自动发起重试。若模型返回无意义空响应，系统也不会直接判定任务失败，会根据前文是否有工具调用，匹配对应的自愈提示词，引导模型继续输出有效内容。只有重试次数达到上限后，才会触发降级兜底策略。

### 2.2 标准化工具调用执行链路

Mini Code的工具调用摒弃了直接函数调用的简易写法，设计了一套标准化的执行链路。所有工具请求都会先进入ToolRegistry.execute注册中心，首先匹配对应的工具实现，再通过zod做参数格式校验，校验通过后执行tool.run核心逻辑。

整套链路内置全局异常捕获机制，无论工具执行出现参数错误，运行报错还是网络异常，都会被统一封装为标准ToolResult结构体，不会让单个工具异常打断整个Agent Loop循环。同时系统会标记本轮工具执行状态，记录错误次数，为后续异常自愈提供数据支撑。

针对工具返回超大内容的场景，Mini Code设计了replaceLargeToolResult机制，不会把超长文本直接塞入上下文，而是将完整结果持久化保存到本地文件，仅在会话中保留文件路径和精简预览内容。既控制了上下文token消耗，又完整留存了原始数据，兼顾性能与可追溯性。

### 2.3 批量工具执行与人工介入处理

Mini Code支持批量并行处理多条工具调用请求，执行逻辑遵循统一规范。先初始化工具结果数组，遍历执行每一条调用请求，记录执行状态和结果，所有工具全部执行完毕后，统一做token预算校验，批量构造assistant_tool_call和tool_result会话消息，一次性追加到消息队列中。

在人工介入场景上，系统做了精细化优化。当某一个工具结果标记awaitUser: true需要用户补充信息时，不会立刻中断批量执行，而是坚持完成本轮所有工具调用，保证批量任务的完整性。全部执行完毕后，再将需要用户解答的问题封装为assistant消息对外展示，优雅实现人机协同交互。

## 三、cleanup收尾机制，保障每一轮交互状态闭环

如果说execute机制负责把事做好，那么cleanup机制就是负责把事收好。一次智能体交互回合结束后，无论任务正常完成，等待用户输入，异常失败还是触发步数上限，都需要一套完整的收尾逻辑，完成状态回收，会话同步，权限清理，UI重置等工作。

Mini Code将cleanup划分为循环内收尾和循环外收尾两大层级，内层负责判定回合结束形态，外层负责全局状态和持久化数据的同步，全方位避免状态残留，权限泄露，界面卡死等工程级问题。

### 3.1 循环内部收尾，定义回合终止形态

runAgentTurn函数执行完毕后，系统会根据六种不同场景，匹配对应的收尾逻辑。

一是等待用户应答场景，检测到工具结果包含awaitUser标识，提取问题封装为assistant消息同步至会话，同时更新TUI界面展示，暂停循环等待用户输入。

二是无人工介入的工具执行场景，仅完成工具调用无最终文本回复，不判定任务结束，继续进入下一轮模型请求，让模型基于工具结果继续决策下一步动作。

三是正常任务结束场景，模型输出纯文本最终回复，生成标准assistant消息存入会话，正式终止本轮交互。

四是空响应重试耗尽场景，多次自愈重试后仍无有效输出，自动生成兜底提示消息，标记本轮任务失败并退出循环。

五是最大步数强制收尾场景，为避免智能体无限死循环，设置单轮最大step上限，达到上限后主动终止循环，追加提示消息告知用户任务已达步数限制。

六是上下文压缩状态同步场景，执行context collapse上下文折叠后，会话消息结构发生隐性变化，这类状态无法直接通过消息队列返回，需要在回合结尾同步至全局状态管理层，保证内外状态一致性。

### 3.2 循环外部收尾，全局资源与状态规整

跳出单次回合函数后，Mini Code还会执行五项全局收尾操作，构成完整闭环。

首先是权限清除，清空当前回合临时开放的文件编辑，命令执行等权限，严格隔离回合级权限作用域，防止临时权限泄露到下一轮交互，规避安全风险和操作边界混乱问题。

其次是会话消息覆盖，将本轮执行生成的最新消息队列同步替换全局会话消息，保证上层会话状态与实际执行结果完全对齐。

再者是会话持久化保存，系统会自动将会话记录保存为JSON文件，区分全新会话，历史接续会话和上下文压缩会话三种模式。全新会话完整保存除系统提示词外的所有消息，历史接续会话只增量保存新增消息，压缩会话保留原始完整记录的同时存储摘要映射关系，兼顾存储空间和历史可追溯性。

然后是UI状态恢复，智能体执行期间会开启界面忙碌状态，回合结束后强制重置为空闲状态，避免界面一直处于加载卡顿状态，优化用户交互体验。

最后是悬浮工具状态清理，若工具执行中途出现异常报错，可能导致TUI界面残留正在运行的工具标识，收尾阶段会自动校正界面状态，标记异常工具为执行失败，保证界面展示与实际运行状态一致。

## 四、compact上下文分层压缩机制，解决长会话内存溢出难题

代码智能体长期运行会不断积累对话历史，工具执行日志，代码修改记录，导致上下文token持续膨胀，不仅会增加模型调用成本，还会触发上下文溢出，造成智能体失效。Mini Code没有采用单一粗暴的全文总结方式，而是设计了五层分层compact压缩机制，遵循低成本优先，低破坏优先的原则，根据上下文token占用比例，逐级触发不同压缩策略，精准管控上下文预算。

### 4.1 压缩基石，实时Token统计

所有压缩策略的前提都是精准的token实时统计，系统持续计算当前会话上下文总token数量，对比预设上限阈值，按照50%，70%，75%，临界溢出四个档位，依次触发不同层级的压缩动作，实现按需治理，避免过度压缩丢失关键信息。

### 4.2 轻量化无模型压缩策略

这类策略无需调用大模型，仅通过本地规则处理，成本最低，响应最快，优先被系统触发。

MicroCompact在上下文占用达到50%时触发，主要清理低价值旧工具输出，针对read_file，command，search_files，list_files等可重复执行的工具，将久远的冗余输出替换为占位符，在不影响当前任务链路的前提下，快速削减token占用。

SnipCompact触发阈值为70%，采用安全中段裁剪策略，保留系统初始提示词和最近12条核心消息，直接删除中间无关键逻辑的历史对话，单次可减少两千以上token。裁剪过程刻意保护近期代码编辑记录，错误日志和用户最新需求，优先保留对当前任务有价值的上下文信息。

Tool Result Storage属于嵌入式压缩策略，贯穿整个execute执行阶段，针对单次超大工具输出，直接落盘保存到本地文件，上下文仅留存精简预览和文件路径，从源头遏制单次输出撑爆上下文的问题。

### 4.3 大模型智能压缩策略

当轻量化规则压缩无法控制上下文增长时，系统会调用大模型进行智能摘要折叠，分为视图折叠和真实替换两种模式。

Context Collapse在上下文占用75%时触发，调用模型对老旧对话片段生成摘要，但仅修改传给模型的视图消息modelMessages，不会改动原始会话记录transcript。同时设置多重保护规则，不折叠最近12条消息，不拆分工具调用与结果配对，单次最多生成两个摘要片段，在精简模型输入的同时，完整保留原始历史记录，方便后续溯源复盘。

Auto Compact是最高等级自动压缩，触发上下文临界溢出时执行，会真实改写会话消息队列。核心流程为保留系统提示词，划定历史消息保留边界，将边界前的老旧对话交给模型生成统一摘要，最终形成系统提示词加摘要加近期最新消息的精简结构。边界划定遵循三条原则，至少保留6条核心消息，最多限制四万token，绝不拆分工具调用配对，平衡精简效果与任务完整性。

### 4.4 手动压缩与策略横向对比

Mini Code开放了手动压缩命令，用户可根据自身需求主动介入治理，

```
/compact 触发全自动整体摘要压缩
/snip 触发安全中段裁剪压缩
/collapse 触发对话视图折叠摘要
```

手动模式弥补了自动压缩的灵活性不足，用户可在任务节点主动清理历史，适配特殊复杂项目的上下文治理需求。

为方便直观理解，可将所有压缩策略做横向对比，无模型策略成本低速度快，适合日常轻量化治理，大模型摘要策略压缩效果更强，适合长周期复杂任务，视图折叠不破坏原始记录，真实替换彻底精简会话结构，各自适配不同应用场景。

### 4.5 完整压缩流程实战演示

假设智能体经历多轮交互，完成bug修复，代码读取，文件编辑，功能优化等一系列操作，会话历史冗长且token占用超标。新一轮用户请求发起后，系统首先统计token占比，若超过50%先执行MicroCompact清空老旧工具输出，达到70%触发SnipCompact裁剪安全中段历史，仍超标则执行Context Collapse折叠老旧对话视图。若依旧濒临溢出，本轮第一步直接执行Auto Compact重构整个会话消息。后续工具执行产生超大输出时，自动走Tool Result Storage落盘机制，本轮结束后同步保存压缩后的会话记录，整套流程全自动闭环，无需人工干预。

## 五、设计思想提炼，工业级代码智能体的核心设计启示

通读Mini Code基于Agent Loop的完整设计，抛开具体代码实现，更值得开发者学习的是其背后的工程化设计思想，这也是Claude Code这类成熟产品能够稳定落地的关键。

首先是全场景异常兜底设计。工业级智能体不能依赖理想的模型响应，必须考虑空响应，内容截断，工具异常，步数超限等各类边界场景。Mini Code为每一种异常都设计了自愈重试，降级兜底，状态回收机制，不让单一微小故障导致整个智能体循环崩溃，极大提升了运行稳定性。

其次是精细化上下文预算管理。上下文是代码智能体的核心资源，不能放任无序增长，也不能一味粗暴压缩。Mini Code采用分层分级的治理思路，先规则后模型，先局部后整体，能不改动原始消息就只修改模型视图，必须精简时也优先保留核心业务上下文，把token资源用在关键任务链路中。

再者是状态机思维贯穿全程。Agent Loop不是简单的while循环，而是一个完整的有限状态机。每一轮交互都有明确的起始，执行，收尾，压缩流程，每一种响应形态对应固定的状态流转规则，消息，权限，UI，工具，会话五大状态全程同步闭环，杜绝状态不一致，残留泄露等工程隐患。

最后是解耦分层的架构设计。执行逻辑，收尾逻辑，上下文压缩逻辑完全解耦，各自独立迭代又协同配合。新增响应类型只需扩展execute解析规则，新增压缩策略只需接入compact分层体系，不会牵一发而动全身，极大降低了智能体后续迭代和功能扩展的成本。

## 结语

Mini Code作为Claude Code的最小化复刻项目，褪去了商业产品的复杂业务封装，直白展现了代码智能体Agent Loop的底层骨架。execute机制搞定全场景响应解析与工具调度，cleanup机制实现每一轮交互的状态闭环，compact机制解决长会话上下文膨胀难题，三者共同构成了工业级代码智能体的核心三角架构。
