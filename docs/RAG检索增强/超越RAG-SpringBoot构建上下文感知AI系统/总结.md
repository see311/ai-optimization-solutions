# 超越 RAG：Spring Boot 构建上下文感知 AI 系统

> 总结使用: MiniMax M2.5

## 一、RAG 的企业级局限

RAG 擅长解决"找什么信息"，但不负责建模运行时上下文：

| 问题 | 说明 |
|------|------|
| 用户身份差异 | 不同角色需要不同回答，受权限控制 |
| 会话连续性 | 后续问题需基于前文理解 |
| 领域规则约束 | 合规要求、审批流程、访问控制 |
| 流程状态影响 | 不同阶段正确答案不同 |

**典型问题**：回答事实正确，但在上下文上不合适；类似问题不同用户回答不一致；难以解释和审计。

## 二、CAG 架构模式

### 核心概念
- **CAG = Context-Augmented Generation**（上下文增强生成）
- 在 RAG 基础上引入显式上下文管理器
- 不替代检索或生成，而是引入独立的上下文管理层

### 与 RAG 的区别
- **RAG**：关注"哪些信息相关"
- **CAG**：关注"这些信息对谁相关、在什么情境下相关、受到哪些约束"

### 架构收益
1. 关注点分离：检索质量、模型行为、上下文影响分别分析
2. 提升测试性、可审计性
3. 与 Spring Boot 设计原则天然契合

## 三、Spring Boot 实现

### 架构图
```
用户请求 → Spring Boot API → ContextManager(上下文管理器) → RAG流程(检索器+向量存储+LLM)
```

### 核心代码结构

**Controller:**
```java
@RestController
public class AiController {
    private final ContextManager contextManager;
    private final RagService ragService;
    
    public AiController(ContextManager contextManager, RagService ragService) {
        this.contextManager = contextManager;
        this.ragService = ragService;
    }
    
    @PostMapping("/ask")
    public String ask(QueryRequest request) {
        Context context = contextManager.buildContext(request);
        return ragService.generateResponse(request.getQuery(), context);
    }
}
```

**Context 对象:**
```java
public class Context {
    private final UserProfile profile;      // 用户属性
    private final SessionState session;     // 会话历史
    private final PolicyConstraints policies; // 领域策略
}
```

### 关键设计
- 上下文管理器是**独立组件**，不嵌入检索器或 LLM
- RAG 组件保持不变，只是请求准备方式改变
- 渐进式扩展，不是整体重构

## 四、生产环境最佳实践

### 1. 上下文作为明确约束
- 清晰的结构划分和责任归属
- 避免无意间的耦合

### 2. 控制上下文范围
- 过多历史会增加延迟和成本
- 优先保留：近期会话、标准化用户属性、影响结果的业务约束

### 3. 保持 RAG 流程稳定性
- 上下文逻辑只存在于 ContextManager
- 不嵌入检索器或 LLM 封装层

### 4. 可观测性
- 记录上下文使用情况
- 支持审计、合规场景

### 5. 降级能力
- 数据不完整是常态
- 必要时使用默认值，不导致整个请求失败

### 6. 避免 ContextManager 过载
- 职责限制在"编排和整理上下文"
- 不做业务层面的解释或决策

### 7. 安全与隐私
- 访问控制、数据最小化、脱敏处理
- 强化企业安全治理机制

## 五、总结

CAG 是 RAG 的演进而非替代，通过引入上下文管理器实现：

1. **保留已有 RAG 投入**
2. **行为一致性提升**
3. **可追踪性增强**
4. **AI 行为与业务契合**

对于 Java/Spring Boot 团队，CAG 与现有架构模式天然契合，可以较低成本、较小风险渐进引入。
