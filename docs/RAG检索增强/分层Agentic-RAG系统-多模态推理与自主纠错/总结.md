# 分层 Agentic RAG 系统：多模态推理与自主纠错

## 文章概述

本文介绍 **Protocol-H** 架构，解决传统 RAG 系统在处理结构化数据（SQL）和非结构化数据（文档）时的"模态鸿沟"问题。该架构通过 Supervisor-Worker 分层拓扑实现复杂查询的分解与协同执行，结合 Reflective Retry 机制实现自主错误恢复。

## 核心要点

### 1. 模态鸿沟问题
传统 RAG 只能"一次完成"查询，无法同时处理：
- SQL 数据库的结构化推理
- 文档集合的语义检索
- 跨模态的因果关联分析

这导致 30% 的企业查询静默失败，答案遗漏关键数据点或产生幻觉。

### 2. 分层架构设计

**Supervisor（编排器）**
- 元认知决策中心，不直接执行查询
- 负责任务分解、Worker 路由、结果综合
- 核心决策模式：
  ```
  查询分析 → 任务分解 → 路由到 SQL/Vector Worker → 结果综合 → 错误管理
  ```

**SQL Worker**
- Schema 自动发现（通过 INFORMATION_SCHEMA）
- LLM 启发式推断表关系（低置信度需确认）
- 四层安全机制：参数化查询、RBAC、超时保护、结果截断

**Vector Worker**
- 混合检索：BM25 + 向量 + RRF 融合
- 处理冷启动、歧义、时间感知等挑战

### 3. Reflective Retry 机制

**核心创新**：错误发生时进入反思重试模式，而非传播为幻觉。

```python
# 错误流：检测 → 分析 → 修正/回退
error → reflective_retry → corrected_query / alternative_strategy
```

**效果**：幻觉率从 28.5% 降至 7.1%（降低约 60%）

### 4. 性能对比

| 方案 | 准确率 | 幻觉率 | 推理步骤 | 延迟(p95) |
|------|--------|--------|----------|-----------|
| **Protocol-H** | **84.5%** | **7.1%** | 3.2 | 2.1s |
| Flat Agent | 62.8% | 18.2% | 1.8 | 1.4s |
| Standard RAG | 45.2% | 28.5% | 1.0 | 0.8s |

Protocol-H 在复杂多跳问题上准确率提升 21.7 个百分点，错误恢复率达 89%（Flat Agent 仅 12%）。

### 5. 生产级要点

- **StateGraph 确定性编排**：可审计追溯，满足合规要求
- **Adapter 模式**：云无关设计，支持 Snowflake/Redshift/BigQuery
- **Schema 漂移处理**：后台线程定期更新 + 模糊匹配修正
- **成本优化**：Supervisor 用 GPT-4o mini，Worker 用 GPT-4o

## 关键启示

1. **专业化优于通用化**：SQL 和 Vector Worker 各司其职
2. **错误恢复是关键**：60% 幻觉源于执行错误，非 LLM 推理缺陷
3. **分层编排是核心**：无单一 Agent 能同时处理 SQL 和语义数据
