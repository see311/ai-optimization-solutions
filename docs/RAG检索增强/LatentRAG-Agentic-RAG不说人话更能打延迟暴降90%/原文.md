# Agentic RAG不说人话更能打，延迟暴降90% — LatentRAG

> 来源：arXiv 2605.06285 | 2026年5月7日
> 作者：Yijia Zheng, Marcel Worring (University of Amsterdam)

## 核心问题

Agentic RAG 虽然在复杂问答上表现优异，但存在严重的延迟问题——代表方法 Search-R1 的推理时间是传统 RAG 的 16-22 倍。延迟的主要瓶颈在于思维链（CoT）推理和子查询生成阶段，这两个阶段采用自回归逐 token 生成，占总延迟约 90%。

## LatentRAG 核心思路

**"不说人话"**——把推理和检索从离散语言空间转移到连续隐空间（Latent Space）。

传统 Agentic RAG 的流程：
- 生成自然语言思维链（thought）
- 生成自然语言子查询（subquery）
- 用子查询检索文档
- 重复以上步骤

LatentRAG 的流程：
- 直接从隐藏状态生成隐 token 作为 thought 和 subquery（单次前向传播）
- 在隐空间中与密集检索模型对齐，实现基于隐 token 的检索
- 支持端到端联合优化
- 并行隐解码机制：将隐 token 翻译回自然语言，提升可解释性

## 关键创新

1. **隐空间推理**：不再逐 token 生成自然语言 thought，直接在隐空间产出思维向量
2. **隐空间检索**：将 LLM 与密集检索模型在隐空间对齐，用隐 subquery token 直接检索
3. **端到端优化**：推理和检索可联合训练，不再各自为战
4. **并行隐解码**：保留可解释性，隐 token 可翻译回自然语言

## 实验结果

在 7 个基准数据集上：

| 数据集 | 传统 RAG 延迟 | Agentic RAG 延迟 | LatentRAG 延迟 | 延迟比 |
|--------|-------------|-----------------|---------------|--------|
| HotpotQA | 1× | 17.7× | 2.1× | 降88% |
| MuSiQue | 1× | 13.1× | 1.8× | 降86% |
| 2Wiki | 1× | 21.9× | 1.7× | 降92% |

- 性能与显式 Agentic RAG 方法（Search-R1、AutoRefine）相当
- 延迟降低约 90%，接近传统单步 RAG

## 启示

- Agentic RAG 的延迟瓶颈不在检索，而在"说话"——生成自然语言思维链和子查询
- 用隐空间替代自然语言空间，是解决 Agentic RAG 延迟问题的重要方向
- "不说人话"反而更高效，但需要并行解码机制保留可解释性
- 对实时场景（客服、对话式搜索）有直接落地价值
