# 从60%到94%！11个进阶RAG策略

## 核心观点

朴素RAG（Naive RAG）遵循"嵌入查询-检索相似片段-生成答案"的简单流程，存在四大致命缺陷：固定尺寸拆分文档导致语义截断、单一查询视角无法匹配多表述、无相关性过滤返回"相似"而非"相关"结果、小片段缺乏完整上下文。

## 11个进阶RAG策略

### Ingestion策略（文档准备阶段）

| 策略 | 核心逻辑 | 效果 |
|------|---------|------|
| 上下文感知拆分 | 分析语义边界和文档结构，保留片段完整性 | 避免语义断裂 |
| 上下文增强检索 | LLM为片段生成1-2句上下文说明 | 减少35%-49%检索失败 |
| 微调嵌入向量 | 用领域数据训练嵌入模型理解专业术语 | 提升5%-10%准确率 |

### 查询策略（检索阶段）

| 策略 | 核心逻辑 | 效果 |
|------|---------|------|
| 重排序 | 两阶段检索：向量检索筛选 + 交叉编码器重评分 | 大幅提升检索精度 |
| 查询扩展 | LLM将短查询扩展为详细版本 | 更好应对模糊查询 |
| 多查询RAG | 生成多个表述变体并行检索去重 | 提升召回率 |
| 自反思RAG | 评估相关性，不合格则优化查询重检 | 具备自校正能力 |

### 混合策略（组合放大效果）

| 策略 | 核心逻辑 | 效果 |
|------|---------|------|
| 智能体RAG | 为Agent配备多种检索工具自主选择 | 高度灵活自适应 |
| 知识图谱 | 向量检索 + 图数据库捕获实体关联 | 减少幻觉 |
| 分层RAG | 父子片段结构平衡精度与上下文 | 减少检索噪声 |
| 延迟拆分 | 嵌入整篇文档后再拆分，保留长距离上下文 | 充分发挥长上下文优势 |

## 落地Roadmap

- **第1周**：上下文感知拆分替代固定尺寸拆分，测量基准
- **第2-3周**：添加重排序，实现查询扩展（可达80%+）
- **第4-6周**：添加多查询或智能体RAG，自反思
- **第2个月+**：上下文增强检索，知识图谱，嵌入模型微调

## 避坑指南

1. 不要盲目堆砌策略，从组合1开始
2. 必须测量基准性能
3. 优先使用语义拆分替代固定尺寸拆分
4. 重排序是投入产出比最高的策略
5. 至少实现查询扩展
6. 使用智能体RAG提升灵活性
